Sentinel Link setup

Sentinel Link lets RF Sentinel phones share what they detect: each phone of a group shows the devices the others hear on its list, radar and map, marked VIA with the phone's name. Phones reach each other three ways, and you can use any mix of them.

Every path needs the phones to be linked into a group first (step 1). All of them only share while a scan runs, and everything is encrypted with the group's key.

1. Link the phones (once)

  1. Install the same RF Sentinel version on every phone.
  2. On each phone: Settings → Sentinel Link → Open Sentinel Link, and fill in This phone's name. It's the name the others see next to VIA and in "via NAME" alerts.
  3. Put the two phones side by side. Tap Link up a Sentinel on one and Join a Sentinel on the other. Allow "Nearby devices" if Android asks.
  4. Both screens show a 6-digit code. Same code on both: tap Confirm on both. Different code: Cancel on both and start again.
  5. A third phone joins the same way, from any phone already in the group.

The phones agree on the group's key through that code; a phone that wasn't there can't read the group. To leave, tap Leave the group: that phone forgets the key and stops sharing.

2. Bluetooth (phones nearby)

On by default once linked (Share over Bluetooth). Start a scan on both phones: the status reads "Sentinel Link · 1 Sentinel linked" when they're in range, and they find each other again by themselves after going out of range. Their devices show under the Sentinels chip.

For phones that are always far apart, turn Share over Bluetooth off and use one of the paths below, so the status doesn't sit on "waiting for Sentinels".

3. Meshtastic (phones kilometres apart)

What you need

  • One node per phone: a LoRa board running the official Meshtastic firmware, for example a Heltec V3, a LilyGO T-Beam, or a Seeed XIAO ESP32S3 with its Wio-SX1262 LoRa board. A plain ESP32 has no LoRa radio.
  • Its antenna, always screwed on before the node is powered.

Prepare each node in the Meshtastic app

  1. Flash the official firmware if the board doesn't have it (Meshtastic's web flasher).
  2. Connect to it with the Meshtastic app and set Settings → LoRa → Region to your country's region. A node without a region doesn't transmit.
  3. Give both nodes the same modem preset (the default, Long Range - Fast, is fine), the same frequency slot and the same primary channel (channel 0). Leaving every node on the defaults does all of that.
  4. Check they hear each other: each node should list the other in its node list, and a text sent from one reaches the other.
  5. Disconnect the Meshtastic app from the node: a node serves one app at a time.

Connect the node to RF Sentinel

  1. Sentinel Link screen → Meshtastic node → turn on Use a Meshtastic node.
  2. Tap Choose a node and pick yours from the list. If Android asks for a PIN, it's on the node's screen, or 123456.
  3. Start a scan. The status goes through "reading its settings…" and "adding the RFSentinel channel…" to "Meshtastic node · channel N, encrypted".
  4. Do the same on the other phone with its own node.

RF Sentinel adds a private channel named RFSentinel to an empty slot (1 to 7) of the node, with a key made from the group's key. It never sends on the primary channel 0 or a channel you set up, and never to Meshtastic's MQTT. Strangers' nodes may relay your packets but only see encrypted bytes. Within a minute of both phones scanning, the node line reads "heard X ago".

What gets through

A LoRa packet holds about 6 to 19 devices. Watchlist matches go first (within about 20 s, then every minute while heard), flagged devices every 3 minutes, everything else once and again every 15 minutes. Only devices heard in the last 2 minutes are sent, and whitelisted devices never. The receiving phone keeps them listed for 16 minutes. For the most complete picture, keep the sending phone's screen on: with the screen off Android allows only a few WiFi scans an hour.

4. Internet relay (phones anywhere)

Every phone of the group connects to the same MQTT broker. Packets are encrypted with the group's key before they leave the phone and go on a topic made from that key, so the broker only sees encrypted bytes, your IP address and when you send. It uses a few small packets a minute of mobile data and carries far more than LoRa: up to 8 packets every 5 seconds.

  1. Sentinel Link screen → Internet relay → turn on Use an MQTT broker.
  2. Broker: mqtts://broker.example.com (encrypted, port 8883 unless you add one) or mqtt://host:port (unencrypted: the username and password travel in clear, so only on a network you trust).
  3. Username and Password if the broker asks for them.
  4. Check the certificate: leave on. Turn it off only for your own broker with a self-signed certificate.
  5. Same broker on every phone, then start a scan: the status reads "Connected to HOST". Devices from the relay show under the Mesh chip.

Running your own broker

Any MQTT 3.1.1 broker works. With Mosquitto on a server you control, a minimal setup with a password and a TLS certificate (for example from Let's Encrypt) looks like this:

# /etc/mosquitto/conf.d/rfsentinel.conf
listener 8883
certfile /etc/letsencrypt/live/broker.example.com/fullchain.pem
keyfile /etc/letsencrypt/live/broker.example.com/privkey.pem
allow_anonymous false
password_file /etc/mosquitto/passwd

Create the user with mosquitto_passwd -c /etc/mosquitto/passwd sentinel, open port 8883 in the firewall, restart Mosquitto, and enter mqtts://broker.example.com with that username and password on every phone.

5. A phone that only watches

A phone left in the car or at home can show only what the others send: on its Sentinel Link screen, turn on Show only the other Sentinels. While it's in a group it stops its own Bluetooth, WiFi, cell tower, GPS spoofing and drone checks and the online aircraft and Waze feeds; your Settings stay as they are, and hardware plugged into it keeps working. Leave it off on the phones that do the detecting.

6. Check it works

  • Members list on the Sentinel Link screen: each Sentinel shows how it's reached, "Linked now", "Over the mesh · last heard X ago" or "Over the internet relay · last heard X ago".
  • Main list: rows from other phones carry a VIA badge with their name; the Sentinels chip filters Bluetooth ones, the Mesh chip mesh and relay ones.
  • Something stuck? Every status line and its fix is in Sentinel Link troubleshooting.

Q&A

Does Sentinel Link need the internet?

No. Bluetooth and Meshtastic work without any network. Only the internet relay uses mobile data, and only if you turn it on.

How many phones can be in a group?

Any number: each new phone joins from any phone already in the group, with the 6-digit code. Over Meshtastic, every extra phone adds packets to the same slow channel, so keep the interval at the default or longer with many phones.

Can two phones share one Meshtastic node?

No. A node talks to one phone at a time over Bluetooth. Each phone that sends or receives over the mesh needs its own node.

Is it safe to use Sentinel Link on a public Meshtastic mesh?

Other nodes can relay your packets, but they're encrypted twice, by the RFSentinel channel's key and by the group's key, both made from a key only your phones have. They do see that a node is sending, and when. Your packets also use shared air time, so don't set the interval shorter than you need.

Can I use a public MQTT broker?

It works, since everything is encrypted before it leaves the phone, but the broker's owner sees your IP address and when you send, and a public broker can go down or drop clients. Your own broker is better.
